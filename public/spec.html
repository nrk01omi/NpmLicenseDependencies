概要

対象プロジェクトの package.json に書かれた直接依存ライブラリを 1 行ずつ取り上げ、 npm レジストリ API（https://registry.npmjs.org、JSON）から「バージョン・ライセンス・依存ライブラリ」を取得して CSV に出力します。 加えて、設定で npm サイト（npmjs.com）の Dependencies 欄も取得し、3 者の件数を照合できます（npm サイト照合。取得しない設定も可）。

入力package.json（必須）、package-lock.json（任意・推奨）、node_modules/（任意） 問い合わせ先GET https://registry.npmjs.org/<ライブラリ名>/<バージョン> — そのバージョンの package.json 相当の JSON が返ります 出力UTF-8（BOM 付き）の CSV。Excel でそのまま開けます
既定では推移的依存（依存の依存…）は展開せず、直接依存 1 段目だけを扱います。設定「再帰的にすべての依存ライブラリを抽出する」を入れると、依存ライブラリをたどって推移的依存も 1 行ずつ出せます（再帰調査）。

機能番号 ①〜⑥ — 設定と列の対応

画面の設定と結果表の列見出しには同じ番号が付いています。①だけで基本の CSV が出ます（②③は①に含まれます）。④⑤⑥は任意で、必要なときだけ有効にしてください。

リストの作り方 — package.json ∪ package-lock.json

行のリストの作り方は設定「リストの作り方」（CLI --list）で選べます。

選択動き
package.json ∪ package-lock.json（OR で網羅）
既定 / --list union		下の表の両方を拾う和集合。実際にインストールされているライブラリを取りこぼしません。
package.json のみ（従来どおり）
--list package-json（--no-lock も同じ）		この機能を入れる前と同じ動き。直接依存（＋再帰調査でたどれた推移的依存）だけを行にします。

OR のときに拾うものは次のとおりです。

由来拾うもの
package.jsondependencies（設定により devDependencies も）の直接依存と、再帰調査でたどれた推移的依存。
package-lock.jsonルート（packages[""]）に記録された直接依存（optionalDependencies を含む）と、lock に実体があるすべてのパッケージ（ネストされた node_modules/…/node_modules/… も別バージョンとして 1 行）。

再帰調査がたどるのは dependencies だけなので、peerDependencies / optionalDependencies 由来のものや、範囲を解決できなかったものは package.json 側からは拾えません。lock 側からも列挙して OR にすることで、実際にインストールされているライブラリを取りこぼさないようにしています。

  • 重複は 名前@バージョン（再帰調査なしのときは名前）で 1 行にまとめ、両方にあれば「取得元」は 両方
  • lock にしかない行は、深さ＝lock 上のネストの深さ、要求元は空（依存グラフ上の親が分からないため）、備考に lock 上の位置を記載
  • devDependencies を含めない設定では、lock 側の dev / devOptional 扱いのパッケージも加えません
  • 再帰調査なしでも lock 上のパッケージはすべて行になるため、行数は lock の規模（数十〜数百件）になります。件数を抑えたいときは「package.json のみ」を選んでください

参照バージョン — 何のバージョンを見に行くか

依存ライブラリもライセンスもバージョンごとに変わります。例: axios は 1.16.1 で https-proxy-agent が依存に加わったため、1.14.0 なら 3 件、最新版なら 4 件です。 npm サイトのパッケージページは既定で最新版を表示するので、インストール済みと食い違うことがあります（サイトでも /package/axios/v/1.14.0 のようにバージョンを指定すれば一致します）。

設定問い合わせるバージョン用途
インストール済み（既定）
  1. package-lock.json の node_modules/<名前> の version
  2. 無ければ node_modules/<名前>/package.json の version
  3. それも無ければ、レジストリの全バージョンから package.json の範囲指定を満たす最大のもの（semver）
  4. それでも決まらなければ latest（備考に「範囲未解決」と記載）
 実際に配布・実行しているものの監査。CycloneDX との突き合わせ
npm の最新版常にレジストリの dist-tags.latest（キャッシュせず毎回取得）。インストール済みと違えば備考に npm 最新版 X を参照 (インストール済みは Y) npm サイトの表示と同じ内容を得たいとき
最新版モードでは「依存ライブラリ」は最新版の要求、「取得済みライブラリ」は今の lock の中身なので、両者がずれることがあります。lock に無い依存は備考に lock 未解決 と出ます（＝最新版に上げると新たに必要になるもの）。

npm サイト照合 — サイトの Dependencies 欄の取得方法

npmjs.com は Cloudflare がブラウザ以外からのアクセスを 403 で拒否するため、fetch や curl では取得できません。 そこで、利用者のマシンにインストール済みの Microsoft Edge または Google Chrome をヘッドレス（画面なし）で 1 プロセスだけ起動し、 DevTools プロトコル（--remote-debugging-pipe）で同じセッション内にページを順番に開いて、 DOM 内の <ul aria-label="Dependencies"> に並ぶリンクの名前を取り出します。追加の npm パッケージ（Playwright 等）は必要ありません。
1 セッションで Cookie を保持し、間隔を空けて順次アクセスすることで Cloudflare の確認ページ（「しばらくお待ちください…」）が出にくくなり、出た場合も解決を待ちます。

項目内容
取得方法（エンジン） 内蔵（既定）: DevTools プロトコルを --remote-debugging-pipe で直接使う。追加インストール不要。
Playwright: 標準的なブラウザ自動化ライブラリ playwright-core を使う。社内ルール等で「既知のライブラリ経由」にしたい場合に選択。 このツールのフォルダで npm install playwright-core を 1 回実行するだけで使える（ブラウザはローカルの Edge / Chrome を使うので npx playwright install は不要）。 CLI は --site-engine playwright。未インストールなら「サイト未取得」となり、備考にインストール方法が出る。
どちらも「1 プロセス・順次・待ち時間・キャッシュ・確認ページ再試行」の動作は同じで、サイトへのアクセス内容（URL、User-Agent、頻度）も同じ。
取得する／しない設定「npm サイトの Dependencies 欄も取得して照合する」のチェック（CLI は --no-site で取得しない）。しない場合は「npm サイトの dependencies」「一致状態」列が空になり、実行は速くなります。
対象 URLhttps://www.npmjs.com/package/<名前>/v/<バージョン>?activeTab=dependencies。バージョンは「参照バージョン」で決まったもの（インストール済み or 最新版）なので、「依存ライブラリ」と同じバージョンを見ます。
待ち時間（可変）サイトへの連続アクセスを避けるため、取得のたびに設定範囲内のランダムな秒数を待ちます（既定 1～3 秒。CLI は --site-wait 1-3、0 で待たない）。ページは 1 つずつ順番に開きます（並列なし）。キャッシュにあるものは待ちません。
確認ページが出たときCloudflare の確認ページが出た場合は最大 45 秒解決を待ち、それでも通らなければ 15 秒待ってもう 1 回だけ試します。それでも駄目なら「サイト未取得」にして次へ進みます（実行後に「NG をすべて再取得」でやり直せます）。
ブラウザ既定では Program Files 配下の Edge → Chrome の順に自動検出。別の場所にある場合は設定「ブラウザ」（CLI は --browser、または環境変数 NLD_BROWSER）で実行ファイルを指定。
キャッシュ取得結果は .cache/<名前>@<バージョン>.npmsite.json に保存し、次回以降はサイトにアクセスしません（バージョンが決まれば内容は変わらないため。キャッシュにあるものは待ち時間も入れず、ブラウザも起動しません）。 レジストリ応答のキャッシュ（.cache/<名前>@<バージョン>.json）とは別で、設定「npm サイト応答のキャッシュを使う」（CLI --no-site-cache）で個別に無効化できます。ログ末尾の「サイト取得 N 回, キャッシュ M 件」で実際にサイトへ行った回数が分かります。
ブラウザのプロファイル（Cookie）はキャッシュ設定に関係なく .cache/npmsite-browser-profile/ に保持します。「再取得」は結果キャッシュを使いません。
取得できないときブラウザが見つからない、Cloudflare に拒否された、タイムアウト（45 秒）、ページに Dependencies 欄が無い、などの場合は行を落とさず「一致状態」を サイト未取得、備考に理由を記します。レジストリ側の取得は成功しているので行は OK のままです。「NG をすべて再取得」でサイト未取得の行もやり直せます。
サイトの HTML 構造（aria-label="Dependencies" のリスト）が変わると取得できなくなります。その場合は「Dependencies 欄が見つかりません」となるので、取得しない設定で運用してください。

再帰調査 — 推移的依存をすべて抽出する（任意）

設定「再帰的にすべての依存ライブラリを抽出する」（CLI --recursive）を入れると、2 段階で動きます。

段階内容
1. 再帰調査 直接依存を起点に、「依存ライブラリ」（レジストリ上の dependencies）をたどって到達するすべての 名前@バージョン を列挙します（レジストリ API のみ。ライセンスやサイト照合はまだ行いません）。
子のバージョンの決め方（依存ライブラリベース）: ① package-lock.json を Node の解決順（親の直下 → 祖先 → トップレベル）で引く ② lock に無ければ、レジストリの全バージョンから要求範囲を満たす最大のもの（備考に「範囲解決」）。
同じ 名前@バージョン は 1 行にまとめ、「要求元」に親を列挙します。循環参照はこれで止まります。devDependencies / peerDependencies / optionalDependencies はたどりません。
2. 件数の確認 再帰調査が終わると、合計・直接・推移的・最大深さ・lock で決定した数・解決不能数・見込み時間を表示して本調査を開始するか確認します（ダイアログ「本調査を開始」／「中止」。CLI は端末で y/N、--yes で省略）。 npm サイト照合ありのときは 1 行あたり「待ち時間＋数秒」かかるため、件数が多い（数百件）場合はここで判断してください。中止すると CSV は保存しません。
3. 本調査列挙したすべての行について、通常どおりライセンス・依存ライブラリ・取得済みライブラリ・npm サイト照合を実行し、CSV に出力します。

並び順（親子順 / 深さ順）

結果表の「並び」と CSV の並び（設定「並び順」／CLI --order）を選べます。既定は親子順です。

並び内容
親子順（tree） 直接依存を package.json の順に根とし、その直下に子・孫を名前順で深さ優先にぶら下げます。「ある親ライブラリが引き込む子のライセンス」を塊で確認する用途向け。
複数の親から要求されるライブラリ（同じ 名前@バージョン）は、画面では 2 回目以降も親の下に「既出」として薄く表示します（塊が欠けないように。既出の下の子は展開しません）。 CSV も既定で画面と同じ行を出します（設定「CSV も画面と同じ行（既出を含む）」／CLI は既定 ON、--no-duplicates で OFF）。 既出行かどうかは「既出」列、表示上の位置は「表示階層」「表示上の親」列で分かるので、Excel のフィルタで既出を外したり、特定の親の塊だけを見たりできます。 OFF にすると従来どおり最初に現れた位置に 1 行だけ（1 行 1 パッケージ）になります。集計は「既出」が空の行だけを対象にしてください。 このツールで CSV を読み込むときは、既出行は自動的に読み飛ばして表側で展開し直します。
深さ順（depth）直接依存（深さ 0）→ 深さ 1 → 深さ 2 … の順。同じ深さは名前順。
再帰調査は「実際にインストールされている木」ではなく「各ライブラリが要求している依存」をたどります。lock がある限り両者は一致しますが、lock に無い依存はレジストリで範囲解決するため、実環境と異なるバージョンになることがあります（備考に記載）。

⑥ 脆弱性チェック — 既知の脆弱性の有無（任意）

設定「使用しているバージョンに既知の脆弱性があるか確認する」（CLI は --no-vulns で無効化）を入れると、本調査の後に全行分をまとめて確認します。

項目内容
情報源npm レジストリの一括 advisories API POST <レジストリ URL>/-/npm/v1/security/advisories/bulk。npm audit が使っているものと同じで、内容は GitHub Advisory Database（GHSA）。認証は不要。
問い合わせ方結果表の全行（レジストリ取得が成功した行）の 名前 → [バージョン…] をまとめて 1 回 POST（200 件ずつ分割）。応答の advisory ごとの「影響バージョン範囲」に、その行のバージョンが入るかを semver で照合して絞り込みます。
結果「脆弱性」列に なし / あり N 件 (最高 深刻度)、「脆弱性の詳細」列に GHSA-ID・深刻度（CVSS スコア）・タイトル・影響範囲・GitHub Advisory へのリンク。深刻度は critical > high > moderate > low > info。
キャッシュしません。脆弱性情報は日々追加されるため、実行のたびに問い合わせます（1 回の要求で済むので負荷は小さい）。
失敗したときAPI に到達できない／社内ミラーが未対応（404 等）の場合は、行を落とさず「脆弱性」列を 確認失敗、備考に理由を出します。レジストリ URL に社内ミラーを指定している場合、ミラーがこの API を中継していないことがあります（その場合は既定の registry.npmjs.org で実行してください）。
再取得行の「再取得」／「NG をすべて再取得」では、再取得した行の脆弱性も確認し直します。
「脆弱性あり」はそのバージョンに公開済みの advisory があることを示すだけで、実際に悪用可能か（該当機能を使っているか）は判断していません。修正版は各 advisory のリンク先で確認してください。

できること

  • package.json の直接依存ライブラリごとに、バージョン・ライセンス・依存ライブラリ（要求範囲）・取得済みライブラリ（lock の固定バージョン）を 1 行にまとめて CSV 出力
  • devDependencies を含める／含めないの切り替え
  • 参照バージョンを「インストール済み」「npm の最新版」から選択
  • 再帰調査: 依存ライブラリをたどって推移的依存もすべて 1 行ずつ出力（件数を確認してから本調査。深さ・要求元付き）
  • リストは package.json と package-lock.json の OR（リストの作り方）。lock にしか無いライブラリも「取得元」付きで 1 行ずつ出力
  • npm サイト（npmjs.com）の Dependencies 欄を取得して、依存ライブラリ／取得済みライブラリとの件数一致を「全一致／不一致」で表示（取得しない設定も可、待ち時間は可変）
  • スコープ付きパッケージ（@scope/name）の取得
  • lockfileVersion 1 / 2 / 3 の package-lock.json の読み取り
  • レジストリ応答のキャッシュ（.cache/）による高速な再実行。オフラインでも一度取得済みなら完走
  • 429 / 5xx / ネットワークエラーの自動リトライ（内部で 3 回）と、それでも失敗したときの確認ダイアログ（エラー時の動作）
  • NG 行だけを後から再取得（行単位／一括）。再取得後は CSV を自動で保存し直す
  • 保存した CSV の読み込み（「CSV を読み込む…」）。過去の結果を結果表に復元して閲覧・別名保存（再取得は不可）
  • 社内ミラー等の別レジストリ URL の指定（認証なしのもの）
  • Windows のフォルダ選択／保存ダイアログでの入出力指定
  • CLI（node src/cli.js）での同じ処理の実行（バッチ向け）

できないこと・限界

  • 再帰調査での devDependencies / peerDependencies / optionalDependencies の追跡 — たどるのは dependencies のみです（ただし lock に載っていれば lock 側のリストで拾えます。この場合は要求元が空になります）
  • peerDependencies / optionalDependencies — 「依存ライブラリ」には含めません（dependencies のみ）
  • レジストリ以外の依存指定 — git+https://…、file:…、github:user/repo などは、lock / node_modules にバージョンが無い場合「取得失敗」になります（行は残ります）
  • npm サイトの Dependencies 欄以外の取得 — サイトからは Dependencies 欄の名前だけを取り出します。Dev Dependencies、週間ダウンロード数などは取得しません。また Edge / Chrome が無い環境ではサイト照合はできません（レジストリ側の取得は動きます）
  • ライセンス本文の確認 — package.json に宣言された license の値だけを見ます。LICENSE ファイルの中身や、宣言と実態の食い違いは検出しません。宣言が無いものは UNKNOWN です
  • 認証が必要なプライベートレジストリ — トークン付きの取得には対応していません
  • モノレポ（workspaces）の横断 — 指定したフォルダの package.json だけを対象にします。複数パッケージは個別に実行してください
  • 同時に複数の解析 — GUI サーバーは 1 度に 1 ジョブです。実行中に「実行」を押すと拒否されます
  • Windows 以外でのネイティブダイアログ — macOS / Linux ではパスを直接入力してください（処理自体は動きます）
  • 削除・非公開化されたバージョンの取得 — レジストリから消えたものは 404 で取得失敗になります

エラー時の動作

取得は最大 5 並列で走り、429 / 5xx / ネットワークエラーは内部で 3 回まで自動リトライします。それでも失敗した場合の扱いは設定「エラー時の動作」で決まります。

設定動作
確認ダイアログを表示する（既定）失敗するたびにダイアログを出して選択を待ちます。並列で複数失敗しても 1 件ずつ順番に確認します。
確認せず自動でリトライする「自動リトライ回数」まで待ち時間（1→2→4 秒…）を置いてリトライし、それでも失敗したら NG のまま次へ。
確認せず失敗のまま次へ進むNG のまま続行（CLI と同じ）。

ダイアログの選択肢

ボタン動作
1 回リトライその 1 件だけもう一度取得。失敗したら再度確認（試行回数を表示）。
以降は確認せず自動でリトライこの件と以降の失敗は、自動リトライ回数まで確認なしでリトライ。上限に達したら NG のまま次へ。
失敗のまま次へ進むその 1 件は NG のまま続行。次の失敗ではまた確認。
以降の失敗もすべて無視して続行以降は確認せず NG のまま進める。

NG になった行は、完了後に結果テーブルの「再取得」（行単位）または「NG をすべて再取得」でやり直せます。再取得はキャッシュを使わず必ずレジストリへ問い合わせ、終わると CSV を保存し直します。

使い方の流れ

  1. 設定 — プロジェクトフォルダ（package.json のある場所）と出力 CSV を指定。必要に応じて devDependencies・参照バージョン・エラー時の動作を選ぶ。入力内容はブラウザに記憶され、次回も復元されます
  2. 実行 — 「▶ 実行」を押すと進捗バーとログがリアルタイムで進みます。NG が出ると（既定では）確認ダイアログが出ます
  3. 結果 — テーブルで確認。「NG のみ」フィルタや名前・ライセンスでの絞り込み、依存ライブラリ／取得済みライブラリは件数クリックで展開
  4. 再取得 — NG 行を「再取得」または「NG をすべて再取得」でやり直す
  5. 保存 — 完了時・再取得後に自動で CSV 保存。「CSV を保存」で別の場所へ保存し直し、「保存先を開く」でエクスプローラーを開けます
  6. 読み込み — 「CSV を読み込む…」で、このツールが保存した CSV を選ぶと結果表に復元されます（展開・フィルタ・並び・脆弱性リンクも復元）。列が少ない古い CSV も、ある列だけで表示します。 読み込んだ結果は元プロジェクトの情報が無いため「再取得」はできません（更新するには同じプロジェクトで「実行」）。「CSV を保存」で別名保存はできます

CLI で同じことをする

node src/cli.js --project <フォルダ> [--out <CSV>] [--include-dev] [--latest] [--no-cache] [--registry <URL>]

CLI は対話できないため、エラー時は「失敗のまま次へ」で動きます。終了コード: 0 = 全件成功、2 = 取得失敗あり（CSV は出力済み）、1 = 実行エラー。

CSV 形式

  • 文字コード UTF-8（BOM 付き）、改行 CRLF、RFC 4180 のクォート。Excel でダブルクリックしても日本語ヘッダーが文字化けしません
  • 列順: ライブラリ名, バージョン, 依存種別, 取得元, 深さ, 要求元, 既出, 表示階層, 表示上の親, ライセンス, 依存ライブラリ, 取得済みライブラリ, npm サイトの dependencies, 一致状態, 脆弱性, 脆弱性の詳細, リポジトリ, 備考 （機能番号: ①①①①⑤⑤⑤⑤⑤①②③④④⑥⑥①－。CSV のヘッダーには番号を付けていません）
  • 「脆弱性の詳細」は 1 セル内に GHSA-ID [深刻度 CVSS] タイトル (影響: 範囲) URL を ; 区切り。⑥を使わない設定では「脆弱性」「脆弱性の詳細」は空
  • 「依存ライブラリ」「取得済みライブラリ」「npm サイトの dependencies」は 1 セル内に ; （セミコロン＋空白）区切り
  • 「一致状態」は 全一致 / 不一致 / サイト未取得。npm サイトを取得しない設定では空
  • 親子順のときは画面と同じ行（既出を含む）を出すため、行数がライブラリ数より多くなります。「既出」が空の行だけがライブラリの実体です
  • 取得失敗の行も残ります（ライセンス欄 取得失敗、備考に理由）
