概要

対象プロジェクトの package.json に書かれた直接依存ライブラリを 1 行ずつ取り上げ、 npm レジストリ API（https://registry.npmjs.org、JSON）から「バージョン・ライセンス・依存ライブラリ」を取得して CSV に出力します。 npmjs.com の Web ページ（HTML）は読みません。

入力package.json（必須）、package-lock.json（任意・推奨）、node_modules/（任意） 問い合わせ先GET https://registry.npmjs.org/<ライブラリ名>/<バージョン> — そのバージョンの package.json 相当の JSON が返ります 出力UTF-8（BOM 付き）の CSV。Excel でそのまま開けます
推移的依存（依存の依存…）は展開しません。全体の網羅は CycloneDX の SBOM に任せ、このツールは「直接依存 1 段目の正確な情報」を担当する設計です。

「依存ライブラリ」と「取得済みライブラリ」の使い分け

依存ライブラリ取得済みライブラリ
意味そのライブラリが要求しているものあなたの環境に実際に入っているもの
出どころnpm レジストリ（ライブラリ側の package.json）対象プロジェクトの package-lock.json
形名前@^1.2.3（範囲）名前@1.2.3（固定）
向いている用途npm サイトとの照合、ライブラリの要求内容の確認CycloneDX（pkg:npm/名前@1.2.3）との突き合わせ、配布物の監査

参照バージョン — 何のバージョンを見に行くか

依存ライブラリもライセンスもバージョンごとに変わります。例: axios は 1.16.1 で https-proxy-agent が依存に加わったため、1.14.0 なら 3 件、最新版なら 4 件です。 npm サイトのパッケージページは既定で最新版を表示するので、インストール済みと食い違うことがあります（サイトでも /package/axios/v/1.14.0 のようにバージョンを指定すれば一致します）。

設定問い合わせるバージョン用途
インストール済み（既定）
  1. package-lock.json の node_modules/<名前> の version
  2. 無ければ node_modules/<名前>/package.json の version
  3. それも無ければ、レジストリの全バージョンから package.json の範囲指定を満たす最大のもの（semver）
  4. それでも決まらなければ latest（備考に「範囲未解決」と記載）
 実際に配布・実行しているものの監査。CycloneDX との突き合わせ
npm の最新版常にレジストリの dist-tags.latest（キャッシュせず毎回取得）。インストール済みと違えば備考に npm 最新版 X を参照 (インストール済みは Y) npm サイトの表示と同じ内容を得たいとき
最新版モードでは「依存ライブラリ」は最新版の要求、「取得済みライブラリ」は今の lock の中身なので、両者がずれることがあります。lock に無い依存は備考に lock 未解決 と出ます（＝最新版に上げると新たに必要になるもの）。

できること

  • package.json の直接依存ライブラリごとに、バージョン・ライセンス・依存ライブラリ（要求範囲）・取得済みライブラリ（lock の固定バージョン）を 1 行にまとめて CSV 出力
  • devDependencies を含める／含めないの切り替え
  • 参照バージョンを「インストール済み」「npm の最新版」から選択
  • スコープ付きパッケージ（@scope/name）の取得
  • lockfileVersion 1 / 2 / 3 の package-lock.json の読み取り
  • レジストリ応答のキャッシュ（.cache/）による高速な再実行。オフラインでも一度取得済みなら完走
  • 429 / 5xx / ネットワークエラーの自動リトライ（内部で 3 回）と、それでも失敗したときの確認ダイアログ（エラー時の動作）
  • NG 行だけを後から再取得（行単位／一括）。再取得後は CSV を自動で保存し直す
  • 社内ミラー等の別レジストリ URL の指定（認証なしのもの）
  • Windows のフォルダ選択／保存ダイアログでの入出力指定
  • CLI（node src/cli.js）での同じ処理の実行（バッチ向け）

できないこと・限界

  • 推移的依存の展開 — 依存の依存は列挙しません。全体の木は CycloneDX 等の SBOM で確認し、本ツールの「取得済みライブラリ」（名前@バージョン）と突き合わせてください
  • peerDependencies / optionalDependencies — 「依存ライブラリ」には含めません（dependencies のみ）
  • レジストリ以外の依存指定 — git+https://…、file:…、github:user/repo などは、lock / node_modules にバージョンが無い場合「取得失敗」になります（行は残ります）
  • npm サイト（HTML）と完全に同じ表示の再現 — サイトは最新版を表示しています。「npm の最新版」モードで近い内容になりますが、サイト独自の表示（週間ダウンロード数など）は取得しません
  • 取得済みライブラリの厳密なネスト対応 — lock のトップレベル（node_modules/<名前>）を見ます。同じ名前が別バージョンでネストされている場合、トップレベルに同名が無いときだけネストを拾うため、「どの親がどのネスト版を使うか」までは追いません
  • ライセンス本文の確認 — package.json に宣言された license の値だけを見ます。LICENSE ファイルの中身や、宣言と実態の食い違いは検出しません。宣言が無いものは UNKNOWN です
  • 認証が必要なプライベートレジストリ — トークン付きの取得には対応していません
  • モノレポ（workspaces）の横断 — 指定したフォルダの package.json だけを対象にします。複数パッケージは個別に実行してください
  • 同時に複数の解析 — GUI サーバーは 1 度に 1 ジョブです。実行中に「実行」を押すと拒否されます
  • Windows 以外でのネイティブダイアログ — macOS / Linux ではパスを直接入力してください（処理自体は動きます）
  • 削除・非公開化されたバージョンの取得 — レジストリから消えたものは 404 で取得失敗になります

エラー時の動作

取得は最大 5 並列で走り、429 / 5xx / ネットワークエラーは内部で 3 回まで自動リトライします。それでも失敗した場合の扱いは設定「エラー時の動作」で決まります。

設定動作
確認ダイアログを表示する（既定）失敗するたびにダイアログを出して選択を待ちます。並列で複数失敗しても 1 件ずつ順番に確認します。
確認せず自動でリトライする「自動リトライ回数」まで待ち時間（1→2→4 秒…）を置いてリトライし、それでも失敗したら NG のまま次へ。
確認せず失敗のまま次へ進むNG のまま続行（CLI と同じ）。

ダイアログの選択肢

ボタン動作
1 回リトライその 1 件だけもう一度取得。失敗したら再度確認（試行回数を表示）。
以降は確認せず自動でリトライこの件と以降の失敗は、自動リトライ回数まで確認なしでリトライ。上限に達したら NG のまま次へ。
失敗のまま次へ進むその 1 件は NG のまま続行。次の失敗ではまた確認。
以降の失敗もすべて無視して続行以降は確認せず NG のまま進める。

NG になった行は、完了後に結果テーブルの「再取得」（行単位）または「NG をすべて再取得」でやり直せます。再取得はキャッシュを使わず必ずレジストリへ問い合わせ、終わると CSV を保存し直します。

使い方の流れ

  1. 設定 — プロジェクトフォルダ（package.json のある場所）と出力 CSV を指定。必要に応じて devDependencies・参照バージョン・エラー時の動作を選ぶ。入力内容はブラウザに記憶され、次回も復元されます
  2. 実行 — 「▶ 実行」を押すと進捗バーとログがリアルタイムで進みます。NG が出ると（既定では）確認ダイアログが出ます
  3. 結果 — テーブルで確認。「NG のみ」フィルタや名前・ライセンスでの絞り込み、依存ライブラリ／取得済みライブラリは件数クリックで展開
  4. 再取得 — NG 行を「再取得」または「NG をすべて再取得」でやり直す
  5. 保存 — 完了時・再取得後に自動で CSV 保存。「CSV を保存」で別の場所へ保存し直し、「保存先を開く」でエクスプローラーを開けます

CLI で同じことをする

node src/cli.js --project <フォルダ> [--out <CSV>] [--include-dev] [--latest] [--no-cache] [--registry <URL>]

CLI は対話できないため、エラー時は「失敗のまま次へ」で動きます。終了コード: 0 = 全件成功、2 = 取得失敗あり（CSV は出力済み）、1 = 実行エラー。

CSV 形式

  • 文字コード UTF-8（BOM 付き）、改行 CRLF、RFC 4180 のクォート。Excel でダブルクリックしても日本語ヘッダーが文字化けしません
  • 列順: ライブラリ名, バージョン, 依存種別, ライセンス, 依存ライブラリ, 取得済みライブラリ, リポジトリ, 備考
  • 「依存ライブラリ」「取得済みライブラリ」は 1 セル内に ; （セミコロン＋空白）区切り
  • 取得失敗の行も残ります（ライセンス欄 取得失敗、備考に理由）
